# Amazon S3 integration

The connector is `connectors/s3` (`s3@1`). It talks to Amazon S3 and to S3-compatible stores (Cloudflare R2, MinIO, DigitalOcean Spaces, Wasabi) over the S3 REST API, signing every request with AWS Signature Version 4. The signer is written in this package from AWS's public description of the algorithm; no AWS SDK is used. It is tested against the example signatures AWS publishes (the SigV4 test suite's `get-vanilla` case and the S3 GET, PUT, bucket-lifecycle, list and presigned-URL examples). Sources were read on 6 October 2026 and are listed at the end.

## Connection

| Field | |
| --- | --- |
| `access_key_id` | The access key ID |
| `secret_access_key` | The secret access key. Taskiem uses it to sign requests and never sends it |
| `session_token` | Only for temporary credentials (STS). They expire, so a connection that uses them stops working when they do |
| `region` | The bucket's region, e.g. `eu-west-2`. Defaults to `us-east-1`. Cloudflare R2 uses `auto`. Other stores document their own (often `us-east-1`) |
| `bucket` | Optional default bucket. A step can name another one |
| `host` | Leave empty for AWS. For an S3-compatible store, the bare endpoint host, e.g. `<account>.r2.cloudflarestorage.com`, `nyc3.digitaloceanspaces.com`, `s3.eu-central-1.wasabisys.com` or `minio.example.com`. No scheme, path or port |
| `port` | Optional. Only for a custom `host` that does not listen on 443 |
| `path_style` | AWS only: `true` addresses buckets as `s3.<region>.amazonaws.com/<bucket>` instead of `<bucket>.s3.<region>.amazonaws.com`. Custom endpoints always use path style |

Addressing: on AWS a bucket is reached at `https://<bucket>.s3.<region>.amazonaws.com` (`.amazonaws.com.cn` for `cn-` regions). Buckets whose names contain dots, upper case or underscores use path style, because a dotted name breaks the TLS wildcard certificate. Custom endpoints are always HTTPS and path style.

**Egress.** The manifest allows `*.amazonaws.com`, `*.amazonaws.com.cn` and `${connection.host}`. A connection's own endpoint host is allowed automatically, so a tenant does not have to add their MinIO or R2 host to an allow-list. The egress guard still refuses hosts that resolve to private, loopback or metadata addresses, so a MinIO on a private network cannot be reached. The connector builds every host name itself from a validated region and bucket, and it does not follow redirects. S3's redirects mean "wrong region", and the connector reports them with the bucket's real region.

## Actions

| Action | S3 operation | Class | Notes |
| --- | --- | --- | --- |
| `put_object` | `PutObject` | idempotent write | Text or base64 `body`, `content_type`, `cache_control`, `content_disposition`, `metadata`. Sends `Content-MD5`, and the body's SHA-256 is signed. At most 10 MiB |
| `get_object` | `GetObject` | read | `encoding` `text` (must be UTF-8) or `base64`. `max_bytes` defaults to 1 MiB, at most 10 MiB. A larger object fails the step rather than being cut short |
| `head_object` | `HeadObject` | read | A missing object returns `exists: false`. This is also how a missing bucket looks, because HEAD responses have no body |
| `list_objects` | `ListObjectsV2` | read | `prefix`, `delimiter`, `start_after`, `max_keys` (≤ 1000). Pass `next_continuation_token` back as `continuation_token`. Asks for `encoding-type=url` and decodes keys. Also the connection test, which needs the connection's default bucket |
| `delete_object` | `DeleteObject` | idempotent write | Deleting a missing key succeeds. In a versioned bucket it adds a delete marker unless `version_id` names a version |
| `copy_object` | `CopyObject` | idempotent write | Server-side copy, up to 5 GB. Keeps the source's metadata unless `content_type` or `metadata` is given, which replaces it. Detects the error S3 can put inside a 200 response |
| `presign_url` | none (computed locally) | read | A GET or PUT link valid for `expires_in` seconds (≤ 7 days). For PUT, `content_type` is signed, and `headers` lists what the uploader must send |

### Why put, copy and delete are idempotent writes

[action-classes.md](../contracts/action-classes.md) lets an `idempotent_write` retry with the same key after an unknown outcome. S3 takes no idempotency key. These three actions are idempotent by their effect, and a step's input is fixed once recorded:

- **put_object**: writing the same body to the same key again leaves the same object, with the same ETag for a single-part upload.
- **copy_object**: copying the same source to the same key again leaves the same object.
- **delete_object**: a key that is already deleted stays deleted, and S3 answers 204 either way.

In a **versioned** bucket a repeat adds an identical version (put or copy) or another delete marker (delete). The current object is still what one call would have left. If something else writes the key between the first attempt and the retry, the retry overwrites that write. That is the same race a single put has.

The manifest declares the engine key in an input field, `idempotency_key`, because the contract requires an `idempotency` block. The connector only logs the key and never sends it to S3.

### Errors

| S3 says | Step |
| --- | --- |
| `SlowDown`, `ServiceUnavailable`, 503, 429, throttling codes, `RequestTimeout`, `OperationAborted`, `TemporaryRedirect` | Retryable: S3 refused before acting |
| `InternalError` / other 5xx | Retryable for reads. For writes it is an unknown outcome, which the engine retries because all writes here are idempotent |
| Connection refused / DNS failure | Not sent (retryable) |
| Connection lost after sending | Unknown outcome |
| `AccessDenied`, `InvalidAccessKeyId`, `SignatureDoesNotMatch`, `ExpiredToken`, `RequestTimeTooSkewed`, `NoSuchBucket`, `NoSuchKey`, `PermanentRedirect` (with the bucket's region), other 4xx | Fatal |
| CopyObject 200 with an `<Error>` body | Classified by its code, as above. A 200 without a readable `CopyObjectResult` is an unknown outcome |

## Least-privilege IAM policy

Give the connection its own IAM user or role, limited to the buckets and prefixes the workflows use. Drop any action a workflow does not need:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListThePrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::acme-payroll-exports",
      "Condition": { "StringLike": { "s3:prefix": ["taskiem/*"] } }
    },
    {
      "Sid": "ReadWriteObjects",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::acme-payroll-exports/taskiem/*"
    }
  ]
}
```

- `head_object` needs `s3:GetObject`. Without `s3:ListBucket` on the bucket, S3 answers 403 rather than 404 for a missing key, and the step fails instead of returning `exists: false`.
- `copy_object` needs `s3:GetObject` on the source and `s3:PutObject` on the destination.
- Version-specific reads and deletes (`version_id`) need `s3:GetObjectVersion` / `s3:DeleteObjectVersion`.
- A presigned link carries the permissions of the credentials that signed it, for as long as it is valid.
- Buckets encrypted with SSE-KMS also need `kms:Decrypt` (reads) and `kms:GenerateDataKey` (writes) on the key.

For R2, MinIO, Spaces and Wasabi, create an access key restricted to the bucket in that provider's console.

## Limits

- `put_object` takes at most 10 MiB after decoding, and `get_object` returns at most 10 MiB. Step inputs and outputs are stored in the run's history. For larger files, hand the transfer to the client with `presign_url`.
- No multipart upload. Objects up to 5 GB can be copied server-side.
- User metadata must be printable ASCII, with names made of letters, digits, `-` and `_`, and 2 KB in total.
- Object keys must be valid UTF-8, 1 to 1024 bytes, with no `.` or `..` path segment (some HTTP layers normalise those, which would sign one key and address another).
- Custom endpoints must be HTTPS. For tests and sandboxes, the platform can point the connector at an http endpoint with `TASKIEM_S3_URL` (`builtin.Options.S3URL`). Tenants cannot.
- Presigned links are stored in the run's history like any output. Keep `expires_in` short.

## To confirm before go-live

1. **Virtual-hosted style on custom endpoints.** The egress policy allows exactly `${connection.host}`, so `<bucket>.<host>` would be refused. The connector therefore always uses path style there. Path style is documented for R2, MinIO, Wasabi and Spaces. A store that requires virtual-hosted style needs an engine change (allow `*.${connection.host}`).
2. **`encoding-type=url` decoding.** The connector decodes keys with form decoding (`+` is a space), on the assumption that S3 encodes a literal `+` as `%2B`. Check against a bucket holding keys with `+` and spaces, on AWS and each compatible store in use.
3. **Non-ASCII metadata.** It is refused rather than sent, because AWS documents that such values come back RFC 2047-encoded and SigV4 signing of non-ASCII header values is not specified. Decide whether to encode instead.
4. **The SigV4 examples.** AWS's S3-specific signing pages (`sig-v4-header-based-auth.html`, `sigv4-query-string-auth.html`) now redirect to the API reference index. The test vectors in `sigv4_test.go` are the example values those pages published. They all reproduce, but they should be re-checked when AWS republishes the examples.
5. **R2's region.** R2 documents `auto` (with `us-east-1` as an alias). Confirm that R2 accepts both.
