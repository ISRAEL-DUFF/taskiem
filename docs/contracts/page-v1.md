# Contract: Page `page/v1`

A page is a screen a business makes for itself from parts Taskiem draws ([decision 0072](../decisions/0072-pages.md), [the plan](../spec/pages.md), [the guide](../pages.md)). The structure is defined by `schemas/page-v1.schema.json`; this page adds the rules a JSON Schema cannot express. `engine/pages` enforces both: `Parse` what the document says alone, `Check` what needs the business's tables. Every problem is a sentence an owner can act on, with the path it is about (`/blocks/2/source/table`), and never says "block", "schema", "query" or "expression".

## Structure in brief

```json
{ "page": "page/v1", "name": "tickets", "title": "Tickets", "icon": "tables", "about": "Every ticket, newest first",
  "roles": ["support", "manager"],
  "filters": [ { "id": "q", "type": "search" },
               { "id": "st", "type": "choice", "column": "status", "options": [ { "value": "open" }, { "value": "done", "label": "Done" } ] },
               { "id": "when", "type": "dates", "column": "opened" },
               { "id": "mine", "type": "mine", "column": "email", "label": "Mine" } ],
  "blocks": [
    { "id": "head", "type": "heading", "title": "Support desk", "text": "What is open now" },
    { "id": "open", "type": "figure", "label": "Open", "value": "count", "tone": "warn", "lead": true,
      "source": { "table": "tickets", "filters": [ { "column": "status", "op": "eq", "value": "open" } ] } },
    { "id": "owed", "type": "figure", "label": "Owed", "value": "sum", "of": "amount_kobo", "naira": true,
      "source": { "table": "tickets" } },
    { "id": "week", "type": "figure", "label": "Opened this week", "value": "count",
      "change": { "column": "opened", "period": "week" }, "source": { "table": "tickets" } },
    { "id": "list", "type": "list", "title": "Tickets",
      "source": { "table": "tickets", "order": [ { "column": "created_at", "desc": true } ], "uses": ["q", "st", "when", "mine"] },
      "item": { "title": "=row.title", "sub": "=row.customer", "state": { "text": "=row.status", "tones": { "open": "warn", "done": "good" } } },
      "group": { "column": "status", "order": ["open", "doing", "done"] },
      "detail": { "title": "=row.title", "lines": [ { "label": "Customer", "value": "=row.customer" },
                                                     { "label": "Amount", "value": "=row.amount_kobo", "naira": true } ] },
      "empty": "No tickets" },
    { "id": "all", "type": "table", "source": { "table": "tickets" },
      "columns": [ { "column": "title" }, { "column": "amount_kobo", "label": "Amount", "naira": true } ] } ] }
```

- **Top level:** `page` (`"page/v1"`), `name` (`^[a-z][a-z0-9-]{1,23}$`), `title` (1 to 60 letters), optional `about` (200), `icon` (one of Taskiem's: tables, orders, money, invoices, members, box, tag, clock, check, bell, star, place, forms, reports, store, grid), `roles`, `filters`, `blocks`.
- **Parts (`blocks`):** `heading` (`title`, `text`), `figure` (`label`, `source`, `value` `count` or `sum` with `of`, or `output` from a tool, `naira`, `tone`, `lead`, `change`, `alert`), `list` (`title`, `size`, `source`, `item`, `group`, `detail`, `actions`, `status`, `empty`), `table` (`title`, `size`, `source`, `columns` with `edit` on a yes/no one, `detail`, `actions`, `status`, `empty`), `buttons` (`title`, `actions`: the page's own, three at most) and `status` (`title`, `workflow`). A row's detail belongs to its list or table and opens as a sheet from the row, with the row's buttons.
- **A source** is a data table by name (`table`), one of Taskiem's own record views (`records`: `orders`, `invoices`, `deliveries`, `customers`, `staff`), or a made tool that answers at once (`tool`, its `inputs`, the `output` shown): one of them. A table's or a view's has `filters` (conditions every row meets: `column`, `op`, `value`), `order` (up to two columns) and, for a list or a table, `uses` (the page's filters that narrow it). A figure has no `uses`: it stays whole. A tool's has neither conditions nor `uses`: the page's filters reach it through its values (`"inputs": {"month": "=filters.when"}`).
- **A button (`actions`)** is one of: a tool (`tool`, `inputs`, `once`), a signal (`signal`: `workflow`, `name`, and `run` or `to`, `input`), or an approval (`approve`: `workflow`, `run`, `step`); `label` (30 letters) and `when` (an expression; false hides it for that row).
- **`place`** `{"area": "orders"}` shows the published page as a tab under one of Taskiem's areas, after Taskiem's own tabs, while that area is on.
- **Values** shown (`item`, `state.text`, `detail`) are words, or an expression after `=` over `row` (the row, its values written as people read them: dates in Lagos, Yes and No) and `filters` (the page's filter values). `state.tones` gives a tone to each of a state's words.
- **Shapes (`shapes/v1`):** a list's `item` and `state`, and a detail's `title` and `lines`, are a made tool's `list` and `card` answers' shapes ([made tools §7](../spec/made-tools.md#7-the-answer)); a page's detail may have twelve lines where a card in the chat has six.

## Rules

1. **Names.** `name` is unique in the business, never one of Taskiem's own command words in any language that is on (`wdcheck.ReservedCommand`, the list a tool's command is held to), and never a tool's command. A part's and a filter's `id` are unique in the page.
2. **Limits.** 12 parts; at most 4 figures side by side (a fifth needs another part between); one `lead`; 4 filters; 5 conditions on a source; 2 orders; 6 columns in a table; 12 lines on a detail; 20 groups in order and 20 choices.
3. **Sources are checked against the table** through the checked query of decision 0060 (`datatables.CheckQuery`), at publish and again at every view: the table is the business's; every column is the table's (or `id`, `created_at`, `updated_at`); each operator fits its column's type (`eq`, `neq`, `lt`, `lte`, `gt`, `gte`, `contains`, `is_null`, `not_null`; comparisons for numbers and dates, `contains` for words); each value fits its column. Text is matched without regard to case.
4. **A figure.** It counts (or adds up) every row its own conditions pick: `uses` on a figure is refused. `sum` adds up a number column (`integer` or `number`) that is not personal; `naira` draws it as naira from kobo. `change` names a `date` or `datetime` column that is not personal and a `period` (`day`, `week` from Monday, `month`, in Lagos): the figure counts (or adds up) only the rows in this period and says the change on the one before. A total is added up over at most 5,000 rows and says so when it stopped there.
5. **A list's groups** are a column's values (not a personal or json column), in `group.order` first (matched without regard to case), then as they come; a row with none is under "Other".
6. **Filters.** `search` looks in the `columns` it names (words, emails or phones) or every text column; `choice` names a text column and its `options`; `dates` a `date` or `datetime` column (neither on a personal column: narrowing by one would show what the mask hides, a birth date found a day at a time), set to `today`, `week`, `month` or `YYYY-MM-DD..YYYY-MM-DD` (up to a year); `mine` an `email` column, matched to the viewer's email, or a `phone` column, matched to the number they sign in by (written with or without its plus, or a Nigerian number as written at home, 080…). A part may use a filter only when it fits the part's table.
7. **Expressions** read `row.<column>` for a column the table has, and `filters.<id>`; a part a tool feeds reads `outputs.<name>`, `item` (a row of the list it gave) and `filters`; the page's own buttons and a tool's values read `filters` alone. Nothing else (no steps, secrets, environment).
8. **What a viewer is shown.** A page reads with the business's connection and shows what it was made to show to those its `roles` let open it (owners always; none named, everyone in the business). A column marked personal (phones and emails by default) is masked for a viewer without `table.read`, before any expression reads the row; a search by such a viewer leaves personal columns out; a table part is not put in order by a personal column for them; a choice or dates filter on one (a page published before rule 6 said so) is neither drawn nor applied for them. More's cursor is Taskiem's own, taken back only with the order it was given for; rows a part orders by a personal column go on for such a viewer by a skip of the rows shown (through the first 1,000), never by the data API's cursor, which may carry the value a row was ranked by.
9. **A part that cannot be drawn** (its table or a column gone since it was published) is refused at publish, and at view is shown as "This part needs fixing" to those who may edit the page and left out for everyone else.
10. **Taskiem's own records** (`"source": {"records": "orders"}`): a view Taskiem defines with a fixed list of columns a page may name, and nothing else. **orders:** `number`, `customer`, `phone`, `email` (personal), `status`, `kind`, `channel`, `total`, `paid` (kobo), `fulfilment`, `zone`, `delivery`, `placed_at`, `paid_at`. **invoices:** `number`, `customer`, `phone`, `email` (personal), `status`, `kind`, `total`, `paid`, `owed` (kobo), `due_on`, `issued_at`, `paid_at`. **deliveries:** `order`, `customer`, `phone` (personal, the order's), `rider` (read from the rider's sealed name: shown, but never a condition, an order, a search or a choice), `status`, `zone`, `fee`, `owed` (to the rider, kobo: delivered and not confirmed), `paid_how`, `offered_at`, `delivered_at`, `confirmed_at`. **customers** (the debtor book): `customer`, `phone`, `email` (personal, each sealed on its own), `invoices`, `owed` (kobo), `added_at`. **staff:** `name`, `email` (a phone-only sign-in address left out), `roles`, `joined_at`. Each also `created_at`. A view is read as a table is (rules 3 to 6), but its personal columns are masked for every viewer and are never a condition, an order, a search's column, Mine's column, a group, a choice, dates or a sum. Check refuses a view Taskiem does not have and one whose area the business has turned off (orders: the Orders area; invoices and customers: Money and invoices; deliveries: the Online shop; staff are in no area). The viewer needs the read permission of the view's own screen (orders and deliveries: `storefront.manage` or `order.handle`; invoices and customers: `invoice.read`; staff: `member.manage`): without it the part is drawn as `unavailable` ("You cannot see orders."), as is a part whose area was turned off since publishing. A row carries `link`, the record's own screen (orders, invoices, staff). Read only, but for a page's buttons (rule 11).
11. **Buttons** (§7). A list's or a table's `actions` (two) show on each row and its card, the page's `buttons` (three) at its top. Pressing one (`POST /v1/pages/{name}/act`) reads the row again as the part shows it to the presser (rule 8's masking before any expression), checks `when`, and works the values out on the server: nothing the presser sends is a row's value.
    - **A tool's**: the tool (members', in prod) must be one the business has (Check); it opens filled in, exactly as a button on a tool's answer (a `tool_buttons` row of the page, `from_page`): held to the tool's roles (greyed with why in the view, 403 on a press) and `run.start`, its care on the start, `once` spent by the first run, a value shown masked asked and never filled in (a personal column for a presser without `table.read`). The button is minted for what it is pressed on, the same for every viewer: a table's or a view's row by its id, a tool's row by the item itself (its place in the list may change), the page's own buttons by their values; what it was minted with is never changed, so a `once` button is spent for that row alone.
    - **A signal**: the `workflow` must declare it for pages (a `signal` step with that `event` and `"pages": true`, wd/v1; Check refuses any other). It is sent, after a Yes (`yes`), to one run of that workflow in prod, in the business, waiting at such a step (by its id, `run`, or by what it waits for, `to`, its correlation), held to the workflow's roles, and to no other run (`runtime.DeliverSignalToRun`); one that has moved on is 409 `moved_on`. A masked value is never sent. Audited `page.signal`. Sending one needs `run.start` (a key kept to another environment never reaches prod's runs), and the roles are those of the version the run is of, not of the one deployed now.
    - **An approval**: the run must be the workflow's and the approval waiting for the presser; the sheet is the approval's own (`POST /v1/approvals/{run}/{step}`).
12. **A tool as a source** (§5). The tool's care must be "answers at once" (an owner's always ask makes it not), checked at publish and at each view; its `output` must be one it declares, a list for a list, not a list for a figure; its `inputs` only those it asks. At most three parts a tool feeds. It runs as the viewer, counted as any run; what it answered is kept sixty seconds for the viewer, the page and those values (two parts one tool feeds share a run; `page_source_cache`), read from the run each time, masked as a tool's answer is (sealed values masked, an output declared personal masked, every word as messages are), with `worked_at`; a run not finished shows `working`. `POST /v1/pages/{name}/refresh`, and any button pressed on the page, let it go. What a tool answers is for those who may use it: before anything kept is read or the tool started, the viewer is held to the tool's roles, `run.start` and a key's environment; anyone else sees the part as `unavailable` ("Only managers can see this."), in the view, in More, on a row's button (403) and in the chat's short form. Check refuses a tool part whose tool's roles let in fewer people than the page's (a page with no roles, or with a role the tool lacks; owners always may both).
13. **A status part** shows a run of its `workflow` (deployed in prod, in the business): the one the page's address names (`?run=`), else its latest; another workflow's run is never shown. Its state in words (`status`, `words`) is for every viewer; the run itself (`run`, its times, who it waits for) only for a viewer with `run.read`. **A row's own status** (a list's or a table's `status`: `workflow`, and `run` or `to`, an expression over the row, or neither): each row shows a run of that workflow (deployed in prod, in the business) the same way, with the same rules (`run_status` on the row): the run whose id `run` gives; or, by `to`, the newest run of the workflow that waits, or last waited, under what `to` gives (its correlation, kept as a keyed hash: `runs.correlation_key`); or, with neither, the run the page's address names. A value the viewer is shown masked names no run. A row whose run is not found says "Not started".
14. **An alert** (`"alert": true`, a figure that counts a table or a view): while above zero, the chat's alerts show the page's title and the count to those who may open the page (and see the view), and open it.
15. **Ticking in place**: a table's column with `edit` must be a yes/no column of the business's own table, not personal; it is a tick for a viewer with `table.edit`, who changes the row through the tables API.

Rules 1 (but uniqueness), 2, 7, a figure's `uses`, the buttons' shape and the structure are `pages.Parse`; 1's uniqueness, 3 to 6, 10's refusals and 11 to 15's tools, signals, workflows and columns are `pages.Check`; 8, 9, 10's drawing and 11 to 14 are the API (`api/pages.go`, `api/pages_records.go`, `api/pages_actions.go`, `api/pages_alerts.go`) with `pages.ReadFor`, `pages.Shape` and `pages.ShapeTool`.

## In the chat

A page's name (`tickets`, or `/tickets`) on WhatsApp, Telegram or Slack answers with its short form (`api/pages_chat.go`): its figures on a line, the first five rows of its first list or table, how many more, and a link. It is read after Taskiem's own words and the business's tools, only for a published page whose roles let the person open it (anyone else is answered as if there were none), drawn for them as the page is.

**From a notification.** A Tell me message (`notify.tell`) may carry a page button, `{"label", "page", "filters"}` (the page's short name written out; its filters by id, each a value or an expression; no `inputs` or `once`), checked when the workflow is published. It is drawn, on WhatsApp and Telegram, only for a person the page's roles let open it, its filters kept with it (a sealed or masked value left out). Pressed, it is held to the page again for whoever pressed it: the page's short form with those filters and the link `/pages/<name>?filters=<the filters as JSON>`, which the app and the web open with them; anyone else is told they cannot open it.

## Kept up to date

An open page may follow `GET /v1/pages/{name}/live` (server-sent events): `changed` `{"page", "blocks": [ids], "all"}` names the parts whose table, orders or invoices changed (every part, `all`, when the page itself did), at most once in two seconds, and carries no data; the client reads those parts again. Only for a page the viewer may open.

## The file

A page saved as a file (`GET /v1/pages/{name}/export`, `<name>.page.json`) is this document and nothing else, written with two spaces of indent: no rows, no ids of the business, and nothing that carries a personal value: a condition on a personal column with a value, every condition value of a part whose table the business no longer has, a choice filter on a personal column, a group order or state colours by one, and the words of an expression that reads one (each left out, and counted in the `Taskiem-Left-Out` header). Reading one back (`POST /v1/pages/import`) holds it to everything above: Parse refuses what is not a page, and Check against the business it is read into says what it names that the business lacks. A name already taken there becomes the next free one (`tickets-2`).

## Changes

H5 (24 November 2026) added a list's or a table's `status` (each row's run), Mine on a `phone` column and the page button on `notify.tell`, each optional: a document without them is unchanged.

The format is new with G0 (decision 0072). `records` (orders and invoices) was added on 23 November 2026, and deliveries, customers and staff after; G2 added buttons (`actions`, the `buttons` part), the `status` part, tools as sources (`source.tool`, `inputs`, `output`, a figure's `value: "output"`), `alert`, a table column's `edit` and the page's `place`, each optional: a document without them is unchanged. Board and chart (G4) are additions when their phase comes.
